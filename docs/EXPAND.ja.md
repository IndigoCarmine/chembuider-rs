# chembuider-rs Expand機能 全フラグメント一覧

[SHORTCUTS.ja.md §2-4](SHORTCUTS.ja.md#2-4-expandlabel-x--x-ラベルからフラグメントへの展開) で
説明した **ExpandLabel（`x` / `X`）**機能で展開できる、全フラグメント名のカタログです。
「フラグメント名」とは、原子ラベルを `` ` `` 編集でこの文字列に書き換えたのち `x`/`X` を押すと
実構造に展開される、完全一致（大文字小文字区別）の識別子です。

対象バージョン: 2026-07-13 時点の `main` ブランチ（コミット `b094363` 以降、フラグメント
エディタ追加後の `fragments/` ディレクトリを含む）。

---

## 1. Expand の基本動作のおさらい

1. Bond ツールで原子をホバー（またはホットスポットに設定）。
2. `` ` `` を押してラベル編集ボックスを開き、下記カタログの**表示名**（例: `TMS`）を
   そのまま入力して `Enter`。
3. 同じ原子をホバー（またはホットスポット）した状態で `x` または `X` を押す。
4. ラベル文字列と一致するフラグメントが見つかれば、その場で実構造に展開される
   （既存の結合は保持）。フラグメント名でないラベルは、縮約式として読めれば展開される
   （[§7](#7-縮約式フラグメント名と元素記号を続けて書く)）。どちらでもなければ構造は変わらず、
   undo の履歴にも残らない。このとき `ChemStructEditor::unexpanded_label` にそのラベルが入るので、
   組み込み先のアプリはそれを取り出して利用者に知らせることができる（エディタ自身は表示しない）。
   ラベル原子の結合がフラグメントの接続点の原子価に収まらないとき（2 本の結合を持つ `Ph`
   など）も、原子価を超えた構造を作らずにラベルのまま残す。

原子ショートカット表（[SHORTCUTS.ja.md §2-2](SHORTCUTS.ja.md#2-2-原子ショートカットホバー中の原子ホットスポットに適用)）に
デフォルトキーがある名前は、わざわざ Expand を使わずキー一発で配置できます。**Expand が
本当に必要になるのは、デフォルトキーが割り当てられていないフラグメント**（下表で
「既定キー: —」のもの）を使うときです。

> キーを割り当てたい場合は `chembuilder_config.json` の `atom_shortcuts` に
> `{ "key": "任意のキー", "fragment": "フラグメント名" }` を追記してください
> （`assets/default_config.json` と同じスキーマ）。

## 4. データ上の注意（接続点に余分な炭素を持つフラグメント）

Expand では**ラベルの付いた原子そのものがフラグメントの接続点の原子になります**。以前の `Ts`
と `BPin` は接続点として余分な炭素を 1 つ持っていたため、`Ts` と書いた原子が炭素になり、その先に
スルホニル基が付いていました（R–CH₂–SO₂Tol）。現在はどちらも名前どおりの原子（`Ts` は S、
`BPin` は B）が接続点で、余分な炭素は入りません。

`Benz`（–C–CH₂–C₆H₅）と `TEG`（–C–O–CH₂CH₂–O–…）は同じ形のまま残してあります（接続点が
余分な炭素）。ベンジル基には `Bn` を使ってください。

## 5. 特殊名（フラグメントファイルではなくコード側で解決される名前）

`Config::resolve_fragment()`（`src/config.rs:279-295`）は、`fragments` 一覧に一致が無い場合、
以下の名前をコード側で特別扱いします。

| 表示名 | 効果 |
| --- | --- |
| `ring3` 〜 `ring12` | 指定サイズ（3〜12 員）の炭素環をその場で生成 |
| `benzene` | ベンゼン環を生成（`benzene.json` が存在するため通常はそちら経由で解決されるが、無い場合のフォールバックとしても機能する） |

`ring3`〜`ring12` は Expand 専用で、原子ショートカット表の環キー（`v`/`4`〜`8`）とは別経路
（あちらは `AtomAction::Ring` としてキーから直接環サイズを解決するため、フラグメント名
`ring5` 等を経由しない）です。ラベルに `ring6` などと手入力して `x` を押すことでも同じ
6 員環を生成できます。

## 7. 縮約式（フラグメント名と元素記号を続けて書く）

ラベルが**単一のフラグメント名と一致しなかった場合に限り**、フラグメント名・元素記号・個数・
括弧でできた**縮約式**として読みます。結合次数は原子価から決まります。

```
MeOPh    →  CH3–O–C6H5（アニソール）     CN      →  C≡N
CHO      →  C(=O)H                       COOH    →  C(=O)–OH      （CO2H も同じ）
CO2Et    →  C(=O)–O–CH2CH3               NMe2    →  N(CH3)2
SO2Me    →  S(=O)(=O)–CH3                OTf     →  O–SO2CF3
NHBoc    →  NH–C(=O)–O–C(CH3)3           B(OH)2  →  B(OH)2
CH(CH3)2 →  イソプロピル                 NaOMe   →  Na–O–CH3
```

規則（実装は `src/label_chain/condensed.rs`、入口は `label_chain::resolve_label_on`）:
- **先頭の原子が接続点**です。先頭が元素記号のとき、その原子には構造の残りと結ぶ分の原子価が
  ちょうど残っていなければなりません。ラベル原子の結合が 1 本なら 1、2 本なら 2 です。したがって
  `CO` は 2 本の結合を持つ原子の上ではケトンの炭素として展開されますが、鎖の末端では展開されません
  （アルデヒドに化けるため）。結合を持たない原子の上では、1 本あるものとして読みます。
- **水素は直前の原子のもの**（`CH2`、`NH`、`OH`）で、原子としては置かれません（エディタの暗黙の
  水素と同じ扱い）。
- **個数は同じ原子に付く同じ基の数**（`CCl3`、`NMe2`、`SO2`）。**括弧**でくくった基は、まとめて
  1 つの原子に付きます（`CH(CH3)2`、`P(O)(OEt)2`）。
- **基は、入る余地のあるいちばん手前の原子に付きます**。`COOH` は C(=O)OH で過酸ではなく、
  `SO2Me` はスルホンでスルフィン酸エステルではありません。`CH2OMe` の Me は、炭素に余地が
  ないので酸素に付きます。
- **結合次数は原子価から決まります**。S と P が高い原子価をとるのは末端の酸素（`SO2`、`P(O)`）
  によるときだけなので、`SSMe` はジスルフィドです。
- **フラグメントは単結合でつながり**、中身はそのままです。フラグメントの先へ続けて書けるのは、
  続く先が一意なものだけです: 原子 1 個（`Me`）、枝のない鎖（`Et` は末端から）、単純な環
  （`Ph` は *para* 位から）。接続点が 1 つの基（`Ac`、`Boc`、`Ts`、`Bn`、`OH` など）で枝は
  終わります。したがって `AcCl`、`TsCl`、`BnBr` は展開されません。
- **標準の原子価を持たない元素**（`Na`、`Sn` など）は単結合だけです（`NaOMe`、`SnBu3`）。
- **分割は最長一致が優先**ですが、それで読めなければ短い名前でも試します（`OCOMe` に
  コバルトは含まれません）。大文字小文字は区別します。`Ph`（フェニル）と `PH2`（ホスフィノ）は
  別物です。
- **どの原子の原子価もちょうど満たされる読み方が無いラベルは、展開されません**。それらしい
  構造を推測で作ることはしません。例: `CO2`、`PPh3`、`NMe3`（電荷が要る）、`H2O`、`K2CO3`
  （基ではなく化合物の式）、`MeHMe`、`DDP`、`Qq`。`Si` や `P` のような素の元素ラベルも
  そのままです。
- 単一のフラグメント名の挙動は**変わりません**。

### 左向きに書いたラベル

結合が右から来る原子のラベルは、画面上では左向きに書かれます（`COOH` → `HOOC`、
`OMe` → `MeO`）。ラベルを最初から左向きに**入力**した場合も、そのままでは読めず、単位を逆順に
すると読めるなら、そちらで展開します: `HOOC`、`NC`、`O2N`、`MeO`、`HO`、`H2N`、`EtO2C`、
`F3C`、`BocHN`、`AcO`、`(CH3)2N` など。逆順の読みは、元素記号から始まるものに限ります。

### 大文字小文字

大文字小文字を無視するのは、ラベルが**入力されたとおりの綴りでは元素記号やフラグメント名に
まったく分割できず**、しかも大文字小文字だけが違うフラグメント名（または別表記）が**1 つだけ**
あるときに限ります: `ph` → `Ph`、`me` → `Me`、`boc` → `Boc`、`OME` → `OMe`、`bn` → `Bn`。
`CO`、`NO`、`BN`、`PH`、`BOC`（B–O–C と分割できる）のように元素記号として分割できるラベルは、
読めても読めなくても、別の綴りのフラグメント名とは見なしません。`Co`、`No`、`Cn` は元素です。

### 以前の「連続記述」との違い

以前はフラグメント名と元素記号を左から単結合でつなぐだけだったため、`CN` が C–N、`CHO` が
C–H–O、`COOH` が C–O–O–H に展開されていました。`MeOPh`、`NaOMe`、`EtOEt` など、単結合の鎖が
正しいラベルの結果は変わりません。`OH` や `NH2` のような、自分の構造をそのまま綴っている
フラグメント名は、長いラベルの中では原子として読まれます（`MeOPH2` の水素は原子にならず、
ラベルの水素として表示されます）。

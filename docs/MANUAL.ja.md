# chembuider-rs 全操作マニュアル（現行設計版）

このドキュメントは `chembuider-rs` の **現在の実装**（`src/widget/`, `src/molecule/`,
`examples/editor.rs`, `examples/fragment_editor.rs`）を実際に読み、動作を確認したうえで
まとめた操作マニュアルです。README.md / README.ja.md の「操作方法」節は代表的な例のみを
紹介する簡易版ですが、本書はマウス操作・キーボードショートカット・ツールバー・既知の
制限事項までを網羅します。

対象バージョン: 2026-07-13 時点の `main` ブランチ（コミット `b094363` 以降、フラグメント
エディタ追加後）。

---

## 1. アプリケーション構成

このリポジトリはライブラリ（`ChemStructEditor` ウィジェット）であり、実行可能なアプリは
`examples/` 以下に 2 つあります。**キャンバス上のマウス・キーボード操作はどちらのアプリでも
共通**（ウィジェット自体の実装のため）で、異なるのはツールバー・ステータスバーなどの
ホストアプリ側の UI です。

| アプリ | ファイル | 起動コマンド | 対応環境 |
| --- | --- | --- | --- |
| **メインエディタ** | `examples/editor.rs` | `cargo run --example editor` | ネイティブ（Windows/Mac/Linux）／ Web（wasm32、`examples/editor_web/`） |
| **フラグメントエディタ** | `examples/fragment_editor.rs` | `cargo run --example fragment_editor` | ネイティブのみ（`std::fs` を直接使用しており wasm 用エントリポイントが無い） |

- メインエディタのウィンドウタイトルは "ChemBuilder — MOL2 Editor"、フラグメントエディタは
  "ChemBuilder — Fragment Editor"。どちらも初期ウィンドウサイズは 1100×750。
- Web 版のビルド手順は `examples/editor_web/README.md` を参照（`wasm32-unknown-unknown` +
  `wasm-bindgen --target web`、`http://` 経由で配信する必要あり。`file://` では ES モジュールが
  読み込めず動作しない）。
- ネイティブ版は `wgpu` ではなく `glow`（OpenGL）バックエンドを使用（現行 Windows
  ツールチェインでの wgpu-hal/Direct3D12 ビルド不具合の回避のため）。

起動直後の初期状態: ツールは **Bond**、結合の立体表示は **None**、配置元素は常に炭素（後述）。

## 2. ツール共通操作（Select / Bond / Eraser のいずれでも有効）

以下はどのツールが選択されていても効く操作です（`src/widget/mod.rs` の `ui()` で、個別ツールの
ハンドラとは別に処理されます。中ボタンのパンはツールのハンドラの後、それ以外はツールのハンドラ
より先に評価されます）。テキスト入力中とクリーンアップ実行中に効くかどうかは、下の
「テキスト入力中・クリーンアップ実行中に効く操作」を参照してください。

| 操作 | 効果 |
| --- | --- |
| マウスホイールスクロール（キャンバス上） | カーソル位置を中心にズームイン/アウト（倍率 0.1〜20.0 にクランプ） |
| トラックパッドのピンチズーム | 同上（OS/ブラウザのピンチジェスチャ由来の `zoom_delta` を使用） |
| 中ボタン（ホイールボタン）を押しながらドラッグ | **キャンバスをパン（平行移動）**。Select / Bond / Eraser のどのツールでも同じ。左ボタンのドラッグと違い、選択・投げ縄・原子の移動・結合の作成は起きない |
| `Ctrl` + `1` / `2` / `3` | ツールを **Select / Bond / Eraser** に切り替え（ツールバーのボタンと同じ。`Ctrl` 付きなので、数字キー単独の原子・結合ショートカットとは別） |
| `Ctrl` + `Z` | Undo（元に戻す） |
| `Ctrl` + `Y` または `Ctrl` + `Shift` + `Z` | Redo（やり直し） |
| `Ctrl` + `C`（または OS の Copy/Cut イベント） | 選択中の原子をコピー。**選択が空の場合は分子全体をコピー** |
| `Ctrl` + `V` | ペースト（下記「クリップボード」参照） |
| `Ctrl` + `K` | バックグラウンドの 2D クリーンアップを開始／実行中なら中止（トグル） |
| `Ctrl` + `0` | 全体表示: 原子・結合・ラベルを含む分子全体がキャンバスの中央に収まるようズームとパンを合わせる（`fit_view` と同じ処理。ビューを変えるだけなのでクリーンアップ実行中も有効） |

これらはツールバーのボタン（後述）からも同じ処理を呼び出せます（Paste ボタン、Clean Up ボタン
など）。

### 結合の右クリックメニュー

結合を右クリックすると ChemDraw 風のメニューが開きます（`examples/editor.rs` と
`chembuilder-office`。どのツールでも有効）。開いている間、対象の結合は緑で表示されます。
現在の値にはチェックが付き、どの項目も Undo 1 回で元に戻せます。

| 項目 | 効果 |
| --- | --- |
| 一重結合 ▸ 実線 / 破線 / ハッシュ / ハッシュくさび / 太線 / 太線くさび / 中抜きくさび / 配位結合 / 波線 | 単結合にして線種を変える。くさびと配位結合の矢印は始点（描き始めた原子）が細い側／矢の根元 |
| 二重結合 / 三重結合 / 四重結合 | 次数を変える（線種は実線に戻る）。次数を上げるとフラグメント由来の H は自動で消える |
| 二重結合の位置 ▸ 自動 / 左 / 中央 / 右 | 二重結合の 2 本目の線の側（始点→終点の向きで見た左右）。二重結合のときだけ有効 |
| 結合を削除 | その結合だけを削除（原子は残る） |

新しい線種・四重結合・二重結合の位置は CDX / CDXML にも保存されます（ChemDraw の Hash・HollowWedge・
Dative・DoublePosition）。ホストアプリに組み込むときは `ChemStructEditor::show` の応答に
`context_menu` を付け、中で `bond_menu` を呼びます（`src/widget/bond_menu.rs` 冒頭の例を参照）。

### テキスト入力中・クリーンアップ実行中に効く操作

「テキスト入力中」は、原子ラベル編集ボックス（バッククォートで開く、後述）が開いている間、
またはツールバーのテキストフィールド（Fragment 名など）にフォーカスがある間
（`egui_wants_keyboard_input()`）です。「クリーンアップ実行中」は、2D クリーンアップの
ワーカーが座標を書き換えている間です。

| 操作 | テキスト入力中 | クリーンアップ実行中 |
| --- | --- | --- |
| 各ツールのマウス操作・キー操作（§3〜§5） | 無効 | 無効（ワーカーと座標の書き換えが競合するため） |
| 中ボタンドラッグのパン | 無効 | 無効 |
| ホイール／ピンチのズーム | 有効 | 有効 |
| `Ctrl` + `0`（全体表示） | 無効 | 有効 |
| `Ctrl` + `1` / `2` / `3`（ツール切り替え） | 有効 | 有効（切り替えたツールの操作は終了後に効く） |
| `Ctrl` + `K` | 有効 | 有効（実行中なので中止になる） |
| `Ctrl` + `Z` / `Ctrl` + `Y` / `Ctrl` + `Shift` + `Z` | 有効（キャンバスの Undo/Redo が実行される） | 有効。Undo はクリーンアップを取り消し（実行中の処理を破棄して開始前の構造に戻す。途中の座標は Redo 履歴に残らない）、Redo は処理を止めてからやり直しを行う |
| `Ctrl` + `C` / `Ctrl` + `V` | 無効 | 有効（ペーストはクリーンアップをその時点の配置で止めてから貼り付ける） |

### Undo / Redo の仕様

- Undo スタック・Redo スタックはそれぞれ最大 **50 件**（`VecDeque`、上限超過で古い方から破棄）。
- 変更操作の直前に `push_undo()` でスナップショットが積まれる方式。Eraser ツールでの削除も含め、
  すべての変更操作が対象（かつては Eraser だけ `push_undo()` を呼んでおらず削除内容が復元
  できない既知の非対称仕様があったが、修正済み）。
- Undo/Redo を行うと選択状態・ホットスポット・ラベル編集中の状態はクリアされます。

### クリップボード（コピー／ペースト）

- **Windows**: コピーは平文テキスト＋自前 JSON 形式に加えて、ChemDraw 互換の **CDX**・透過
  **PNG/DIB 画像**・**OLE オブジェクト**を同時に書き込みます（PowerPoint 等に貼り付けると
  ChemDraw 図として編集可能な形で埋め込まれます）。ペーストは Windows の生キー状態
  （`GetAsyncKeyState`）で Ctrl+V を検知し、① 自前 JSON形式 → ② ChemDraw CDX → ③ 平文テキスト
  の優先順で読み込みを試みます（egui 標準の `Event::Paste` はテキストにしか反応しないため、
  CDX 等の非テキスト形式を拾うのに独自検知が必要）。
- **Windows 以外**: コピー／ペーストは平文テキスト（自前 JSON 形式のシリアライズ）のみで、
  egui 標準の `Event::Copy`/`Event::Paste` を使用します。
- ペーストされた構造は、既存の構造から 1 結合長分オフセットした位置に追加されます。

### 2D クリーンアップ（レイアウト自動整形）

- `Ctrl+K` またはツールバーの **✨ Clean Up** ボタンで開始／**⛔ Stop** で中止するトグル動作
  （`src/molecule/cleanup.rs`）。分子が空の場合は何もしません。
- 開始直前に 1 回だけ Undo スナップショットが取られるため、クリーンアップ後に **Ctrl+Z 1回で
  クリーンアップ前のレイアウトに戻せます**。
- 実行中に Undo すると、クリーンアップそのものの取り消しになります。実行中の処理は破棄され、
  開始前の構造に戻ります（途中まで緩和された座標は Redo 履歴に積まれず、Redo 履歴は開始前の
  ままです）。Redo・ペースト、ホスト側でキャンバスを差し替える操作（サンプルの Clear、
  Fragment の読み込み、反応スキームの構造をキャンバスで編集）は、処理をその時点の配置で止めて
  から行われます（`ChemStructEditor::cancel_cleanup`）。
- 内部は FIRE（Fast Inertial Relaxation Engine）法による力学緩和（結合長ばね・結合角ばね・
  非結合原子間の反発・環交差の補正）。ネイティブではバックグラウンドスレッドで実行され、
  Web（wasm32、スレッド不可）では 1 フレームごとに少しずつ緩和を進めるチャンク実行に
  なります。いずれも実行中はプレビューとして原子位置がリアルタイムに更新されます。
### 反応式のクリーンアップ（矢印を基準に整列）

- `Ctrl+Shift+K` またはツールバーの **⚗ Clean Up Reaction** ボタン
  （`ChemStructEditor::cleanup_reaction`、本体は `src/molecule/reaction_cleanup.rs`）。
  ページに矢印が 1 本もなければ何もしません（実行中の通常のクリーンアップも止めません）。
- 矢印は動かしません（矢印の中心座標は前後で同じ）。各構造式は単独で 2D クリーンアップ
  （`cleanup_2d`）をかけた形になり、構造式・`+`・その他のテキストは矢印軸の高さに上下中央
  揃えされ、今の左右順のまま外接矩形どうしの**すき間が均等**になるよう並べ直されます。
- 矢印の上下に書いた試薬・条件（テキストや構造式）は矢印に付随するものとして矢印と一緒に
  固定されます（構造式はクリーンアップ後も軸からの距離を保ちます）。構造式のすぐ下の
  キャプション（化合物番号など）は構造式と一緒に動きます。反応表・括弧は対象外です。
- 多段反応では各矢印を固定し、矢印と矢印の間はその区間の空きを均等に分け、最初の矢印の
  前と最後の矢印の後は、その行の今のすき間の平均（下限あり）で並べます。矢印と矢印の間が
  狭すぎて、すき間 0 でもその区間の Object が入りきらないときは、その区間の Object は
  動かしません（矢印に重ねたり矢印の向こうへ押し出したりしないため。区間は手で広げてください）。
- 高さの違う矢印は、わずかな差でも別の行として扱い、各 Object は高さの近い行に入って、その
  行の矢印軸の高さにそろえられます（2 本の矢印の中間の高さには置きません）。
- 通常のクリーンアップと違いその場で最後まで計算し（バックグラウンド実行しない）、
  **Ctrl+Z 1 回でクリーンアップ前に戻せます**。通常のクリーンアップが実行中なら、その時点の
  配置で止めてから行います。

## 3. Select ツール

マウス操作（`process_select_tool`, `src/widget/interact.rs:301`）:

| 操作 | 効果 |
| --- | --- |
| 原子をクリック | その原子の選択を **トグル**（選択済みなら解除、未選択なら追加） |
| 何もない場所をクリック | 選択をすべて解除（結合線をクリックしても同様に解除されるだけで、結合単体は選択できない） |
| 原子または結合を **ダブルクリック** | その原子/結合が属する**連結成分（分子全体）**を一括選択 |
| 何もない場所から左ボタンでドラッグ開始 | **投げ縄（フリーハンド範囲）選択**を開始。ドラッグ終了時にポリゴン内の原子が新しい選択になる |
| 原子上から左ボタンでドラッグ開始 → ドラッグ | その原子（すでに選択中の原子群に含まれていれば選択群全体）をカーソルに追従して移動 |
| `Alt` を押しながら、選択がある状態で左ボタンでドラッグ開始 | 選択の重心を中心に、カーソル角度の変化量ぶん**回転** |
| 中ボタンでドラッグ | キャンバスのパンだけ（§2）。投げ縄・原子の移動・回転は起きず、選択も変わらない |

上のドラッグ操作は左ボタンのドラッグだけが対象です（`PrimaryDrag`, `interact.rs:54`。
中ボタンのドラッグはカメラのパンに使われるため、ツールは左ボタンのドラッグだけを読みます）。

キーボード操作（`handle_keys_select_tool`, `interact.rs:559`）:

| キー | 効果 |
| --- | --- |
| `Delete` / `Backspace` | 選択中の原子（とその結合）をすべて削除。選択が空ならホバー中の原子/結合を削除 |
| `Enter`（原子をホバー中） | その原子を「ホットスポット」に設定 |
| `g` / `G`（原子をホバー中、無ければホットスポット） | その原子をホットスポットに設定 **かつ選択にも追加**（Bond ツールの `g`/`G` との違い） |
| `Space` / `Tab` | ホットスポットを解除 |
| 元素・フラグメントキー（下表、原子をホバー中 または ホットスポットのみの場合） | ホバー中/ホットスポットの原子に元素変更・フラグメント付加を適用 |
| 矢印キー（修飾キーなし、ホットスポット設定時） | ホットスポットをその方向に最も近い隣接原子へ移動（ナビゲーション。原子自体は動かない） |
| `Ctrl`+矢印 **または** `Shift`+矢印（選択あり） | 選択中の原子群を 1 結合長ぶんその方向へ平行移動（Ctrl と Shift は同じ動作に重複割り当て） |
| `Alt`+`→` / `Alt`+`←`（選択あり） | 選択を中心の周りに ±15° 回転（`Alt`+`↑`/`↓` は未割り当て） |

> **注意**: 結合の立体・結合次数を変更するキー（`w`/`d`/`1`/`2`/`3` など）、ラベル編集
> （`` ` ``）、ExpandLabel（`x`/`X`）は Select ツールでは動作しません。これらは Bond ツールでのみ
> 有効です（`handle_keys_select_tool` にはこれらの分岐が存在しない）。

## 4. Bond ツール（デフォルトツール）

マウス操作（`process_bond_tool`, `interact.rs:81`）:

| 操作 | 効果 |
| --- | --- |
| 何もない場所をクリック | 現在の配置元素（常に炭素、後述）の原子を新規配置し、ホットスポットに設定 |
| 既存の原子をクリック | 最適な角度を自動計算し、1 結合長先に新しい原子を生成して結合（既にその方向に原子があればスナップ）。**鎖を伸ばす**動作。新しい原子がホットスポットになる |
| 既存の結合をクリック | その結合の次数を **単結合→二重結合→三重結合→単結合…** の順に循環 |
| 原子から原子へドラッグ | 2 原子間に結合を作成（既に結合があれば次数を循環）。ドロップ先が原子でなければ新規原子を作ってそこに結合 |
| 原子から何もない場所へドラッグ | ドロップ位置に新規原子を作成し、ドラッグ元の原子と結合 |
| 中ボタン（ホイールボタン）を押しながらドラッグ | キャンバスをパン（平行移動）。どのツールでも効く共通操作（§2） |

キーボード操作（`handle_keys_bond_tool`, `interact.rs:443`）:

| キー | 対象 | 効果 |
| --- | --- | --- |
| `Delete` / `Backspace` | ホバー中の原子 or 結合（原子優先） | 削除 |
| `Enter` | ホバー中の原子 | ホットスポットに設定 |
| `g` / `G` | ホバー中の原子 | ホットスポットに設定 |
| `Space` / `Tab` | – | ホットスポット解除 |
| `` ` ``（バッククォート） | ホバー中の原子、無ければホットスポット | インラインのラベル編集テキストボックスを開く（「5. ラベル編集」参照） |
| `x` / `X` | ホバー中の原子、無ければホットスポット | **ExpandLabel**: 原子ラベルが既知のフラグメント名（例: バッククォート編集で "Boc" と入力済みなど）と一致する場合、その場でフラグメント構造に展開し、既存の結合を保持する |
| 矢印キー（修飾キーなし） | ホットスポット原子 | 隣接原子のうちその方向に最も近いものへホットスポットを移動 |
| 元素・フラグメントキー（下表） | 優先順: ①ホバー中の原子 → ②（原子もホバー結合も無い場合）カーソル位置に元素を配置 → ③ホバー中の結合 → ④ホットスポット原子 | 下記「原子ショートカット表」「結合ショートカット表」参照 |

### ターゲット解決の優先順位（重要）

同じキーでも、何をホバーしているかで挙動が変わります（`interact.rs:490-508`）:

1. **原子をホバー中** → その原子に対して元素変更／フラグメント付加を実行
2. 原子もホバー結合も無いが、押したキーが「元素を表す」キー（`O`, `o`, `N`, `n`, `s`, `b` など、
   単原子または非炭素をルートに持つフラグメント）→ カーソル位置に **裸の原子** を新規配置
   （炭素をルートに持つ多原子フラグメント＝ベンゼンなどはこの経路では配置されない）
3. **結合をホバー中**（原子もホバーしていない場合） → 結合ショートカット表を適用（環/フラグメント
   の縁融合、立体、次数）
4. どれもホバーしていないが、**ホットスポット原子がある** → ホットスポットに対して適用
   （鎖の連続伸長など）

### 原子ショートカット表（デフォルト設定 `assets/default_config.json`）

Bond ツールでホバー中の原子／ホットスポット原子に効きます（Select ツールでも原子対象には
同じ表が使われます）。

| キー | 動作 | キー | 動作 |
| --- | --- | --- | --- |
| `0` / `1` | 炭素を 1 個伸ばす | `3` | 炭素を 3 個伸ばす |

#### ヘテロ原子の上で押したとき（対象原子の元素はどうなるか）

フラグメントの**接続原子（ルート）の元素**で決まります（`apply_atom_action()`, `interact.rs`）:

- **ルートがヘテロ原子**のフラグメント（`o`=OH, `n`=NH₂, `q`=OMe, `9`=N₃ など）
  → そのキーが表す元素で対象原子を**置き換える**。炭素の上で `o` を押せば、その炭素が
  O–H の O になります（炭素のまま O がぶら下がるのではない）。
- **ルートが炭素**の骨格フラグメント（`a`/`P`=ベンゼン、`4`〜`8`/`v`/`u`=環、`2`=オキソ、
  `e`=Et, `A`=Ac, `Q`=Boc など）
  → 対象原子の元素と電荷を**そのまま残す**。骨格はその原子から*生やす*ものであって、
  その原子が何であるかは指定しないためです。**N の上で `a` を押せばピリジン**、
  O の上で `6` を押せばテトラヒドロピラン、N⁺ の上で環を作っても電荷は保たれます。
- 例外として **H / D** は保持されません（水素は環の頂点や鎖の一員にはならない末端キャップ
  なので、骨格を生やすと炭素に置き換わります）。

#### フラグメント由来の H は結合が増えると自動で消える

`o`(OH) / `n`(NH₂) / `s`(SH) / `p`(PH₂) / `S`(SiH₃) が連れてくる水素は、ラベルの「H₂」を
実体化したもの＝**空いている原子価の代役**です。そこへ新しい結合が来て原子価が埋まると、
代役の役目は終わるので**超過分だけ自動的に削除**されます
（`Molecule::consume_excess_group_h()`, `molecule/mod.rs`）。

- `n` で置いた 2 つの N を二重結合でつなぐと、その場で余分な H が消えて **Ph–N=N–Ph
  （アゾベンゼン）**になります。以前は不可視の H が残って両方の N に赤い過原子価リングが
  出ていました。
- NH₂ の N の上で `a` を押すと、環結合 2 本が入った時点で H が消えて**ピリジン**になります。
- 判定のしきい値は赤いリングと同じ **最大原子価**（S は 6、P は 5）なので、スルホキシドの
  S–H のような正常な構造は残ります。逆に、既に 6 価まで埋まった S(VI) 中心の上で `s` を
  押すと H はその場で消えるため、**続けて `Delete` を押す必要はありません**（押すと S 本体
  が消えます）。
- **`h` で明示的に置いた H は絶対に消えません。** その結果として過原子価になる場合は赤い
  リングが出ますが、原因の H は画面上に見えているので削除できます。
- 削除は編集操作の経路だけで走ります。ChemDraw インポート・クリーンアップ・ペーストは
  入力どおりの構造を保ちます。

### 結合ショートカット表

Bond ツールで結合をホバー中のみ有効（Select ツールでは無効）。

| キー | 動作 |
| --- | --- |
| `w` | 楔形結合（Wedge Up、手前向き） |
| `W` / `h` | 破線楔（Wedge Down、奥向き） |

## 6. ラベル編集（リッチテキスト）

原子ラベル（元素記号）はカスタムテキストに書き換えられます。

1. Bond ツールで、ホバー中（またはホットスポット）の原子上で `` ` ``（バッククォート）キーを
   押すと、その原子の右上にインラインのテキスト編集ボックスが開きます。
2. 以下の軽量マークアップが使えます:

   | 記法 | 結果 |
   | --- | --- |
   | `_2` / `_{aq}` | 下付き文字（1 文字 または `{}` で囲んだグループ） |
   | `^+` / `^{2-}` | 上付き文字（1 文字 または `{}` で囲んだグループ） |
   | `**text**` | 太字 |
   | `//text//` | 斜体 |
   | `\x` | リテラル文字 `x`（エスケープ） |

   例: `CO_2Et` → CO₂Et、`//t//Bu` → *t*Bu。
3. `Enter` を押す、またはテキストボックスからフォーカスが外れると入力内容が確定します
   （空文字なら変更を破棄）。`Escape` を押すと編集をキャンセルします。
4. **ExpandLabel**（`x` / `X` キー）: ラベルが既知のフラグメント名（例えば `` ` `` 編集で
   "Boc" と手入力した場合など）と一致していれば、その場でフラグメントの実構造に展開されます
   （既存の結合は保持されたまま）。

この機能は Bond ツールでのみ有効です（Select ツールでは `` ` `` も `x`/`X` も反応しません）。

## 8. フラグメントエディタ（`examples/fragment_editor.rs`）

再利用可能な部分構造（フラグメント）をキャンバス全体を使って作成・編集する専用アプリです。
メインエディタからは呼び出せず、独立したバイナリとして起動します
（`cargo run --example fragment_editor`）。

ツールバー（2 段）:

| コントロール | 効果 |
| --- | --- |
| **⬚ Select** / **✏ Bond** / **✖ Eraser** | ツール切り替え（挙動はメインエディタと同一） |
| **✨ Clean Up** ⇔ **⛔ Stop** | 2D クリーンアップ（メインエディタと同じ） |
| **🎯 Set Attach** ＋ ラベル `attach = atom #N` | **選択中の原子が 1 個のときだけ**、それを「接続点（attach atom）」に設定。0 個または複数選択だとエラーメッセージを表示 |
| **Name: [名前欄] 💾 Save Fragment** | **キャンバス全体**を `fragments/<名前>.json` として保存（メインエディタの「選択部分だけ保存」とは異なる点に注意）。接続点は ①明示的に🎯で設定したもの → ②無ければホットスポット → ③無ければ最小 ID の原子、の優先順で自動決定される。保存時に接続点原子が原点に来るよう座標が再センタリングされる |
| **Load: [コンボボックス] 📂 Load** | `fragments/` ディレクトリ内の既存フラグメント JSON を選んでキャンバスへ読み込み（現在のキャンバス内容は置き換えられる）。読み込んだ接続点原子は自動的にホットスポットに設定され、ビューは自動フィット（ズーム/パン）される |
| **🔄 Refresh** | `fragments/` ディレクトリを再スキャンして Load コンボボックスの一覧を更新 |
| **🗑 Clear** | キャンバスと接続点・名前欄をリセット |

ステータスバーには原子数・結合数・ツール・接続点 ID・メッセージが表示されます。

> 使い方の想定フロー: Bond ツールで構造を描く → 接続点にしたい原子を Select ツールで 1 個
> 選択して 🎯 Set Attach → Name 欄に名前を入力 → 💾 Save Fragment。保存された JSON は
> メインエディタの `` x `` (ExpandLabel) や `dispatch_atom_key` 経由のフラグメントキー割り当て、
> および結合融合（`a` キー等）から利用可能になります。

## 8.5 反応スキーム（`examples/reaction_scheme.rs`）— 多段階スキームと ChemDraw 入出力

- **多段階スキーム**: 構造・矢印を続けて並べれば (I) → (II) → (III) のような連続した反応になります。
  ツールバーの **➕ line break** で改行を入れると、その後ろが次の行に回ります（同じ化合物を行末と
  次の行頭に置けば、論文の Scheme と同じ形になります）。**Wrap rows at** をオンにすると、指定幅を
  超えたところでも自動で折り返します。改行はエディタ上で薄い `↵` として表示され、クリックで選択・
  削除できます。
- **化合物ラベル**: 構造の真下をクリックするとラベル（`(I)` など）を入力できます。リッチテキスト
  記法が使え（`**4**` で太字）、**Shift+Enter** で 2 行目（`**4**` の下に `(V)`）、Enter で確定です。
  右クリックメニューの **✎ Edit label** でも編集できます。
- 矢印が 2 本以上あるスキームは描画専用で、Analysis テーブルは表示されません（列は変更されず、
  矢印を 1 本に戻すと再びスキームに追従します）。
- **ChemDraw ファイル**: **📂 Open CDXML/CDX…** で ChemDraw のスキームを読み込み、**💾 Save CDXML…**
  / **💾 Save CDX…** で保存します。保存時は ChemDraw の単位（結合 14.4 pt・文字 10 pt）で配置し直し、
  行ごとに reaction scheme、矢印ごとに step を書き、化合物ラベルは chemical property で構造に
  結び付けます（ChemDraw で開いても反応として認識されます）。読み込みは step / chemical property を
  優先し、無い場合は位置（矢印の上下、構造の真下）から推定します。テーブルは保存されません。
- コマンドライン: `--open scheme.cdxml`、`--multi-step`、`--render out.png`、`--save out.cdxml`。
- CDXML の読み書きには [cdx_file_rs](https://github.com/IndigoCarmine/cdx_file_rs) の CDXML
  コーデックを使っています。

## 9. 既知の制限・注意点まとめ

マニュアル利用者が誤解しやすい／ハマりやすい点を実装ベースでまとめます。

1. **中ボタンドラッグでのパンはどのツールでも効くが、テキスト入力中とクリーンアップ実行中は
   効かない**（§2）。Select ツールでも中ボタンのドラッグは投げ縄や原子の移動にならない。
2. **`` ` ``（ラベル編集）・`x`/`X`（ExpandLabel）・結合ショートカット（立体/次数/環融合）は
   Bond ツールでのみ**有効。Select ツールでは反応しない。
3. **「開く／インポート」操作は存在しない。** クリップボード貼り付けかフラグメント読み込み
   以外に構造をロードする方法はない（MOL2 のインポートも未実装、エクスポートのみ）。
4. **キャンバスに新規配置される裸原子は常に炭素。** 元素を切り替えるツールバーの UI は無く、
   `current_element` は初期値 `"C"` から変更されるコードパスが存在しない。他元素を置くには
   原子ショートカットキー（`O`, `N`, `s` など）かラベル編集を使う必要がある。
5. **Ctrl+Shift+Z 相当の重複割り当てに注意**: Select ツールの選択移動は `Ctrl+矢印` と
   `Shift+矢印` の両方が同じ移動アクションにマップされており、機能的に重複している
   （`assets/default_config.json` の `selection_shortcuts`）。
6. **メインエディタの「Save Fragment」は選択が空だとエラーになる**（フォールバックで分子全体を
   保存したりはしない）一方、**フラグメントエディタの「Save Fragment」は常にキャンバス全体を
   保存する**（選択の有無を問わない）。両アプリで同名ボタンでも挙動が異なる点に注意。
7. **Web ビルドでは `std::fs` を使う機能が動作しない**: `⚙ Save Config`・`➕ Save Fragment`・
   クリップボード貼り付けはブラウザ上では失敗し、ステータスバーにエラーメッセージが出る
   （コンパイルエラーにはならない）。「💾 Save MOL2」だけはブラウザのダウンロードに置き換わり
   機能する。フラグメントエディタ自体、Web ビルド対象外（wasm 用エントリポイントなし）。
8. **CDX / 画像 / OLE クリップボード連携は Windows専用**（`#[cfg(windows)]`）。他 OS ではコピー
   ／ペーストとも平文テキストのみにフォールバックする。
